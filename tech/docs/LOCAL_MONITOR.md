# 로컬 뉴스레터 운영 관리

‘글 반응’ 탭에서는 각 글의 유용해요·더 궁금해요·어려워요·좀 쉬워요 합계와 최근 변경 시각을 확인합니다. 최근 365일 이내에 남기거나 수정한 현재 선택이며, 선택 변경은 한 건을 유지하고 취소는 집계에서 빠집니다. 위 날짜 선택과 관계없이 전체 글을 보여줍니다. 개별 브라우저 식별값과 IP 제한값은 조회하지 않습니다. 자세한 제한과 보관 방식은 [글 반응 수집](ARTICLE_FEEDBACK.md)을 확인해 주세요.

이 PC에서 tools/Open-NewsletterMonitor.ps1 또는 바탕화면의 ‘겜붕이의 노트 관리’ 바로가기로 엽니다. 기존 TeamHJD 서버 관리와 같은 계열의 어두운 HTML 화면입니다. 공개 사이트의 관리 페이지는 만들지 않습니다.

화면을 ‘요약·통계’, ‘구독자 목록’, ‘발송 내역’ 탭으로 나눕니다. 상단의 구독 중·인증 대기 카드를 누르면 해당 상태의 목록으로 이동합니다. 목록에는 상태별 필터, 전체 이메일·도메인 검색, 가입·인증·최근 메일순 정렬과 25명 단위 페이지를 제공합니다. 기본 주소는 마스킹하며 운영자가 ‘이메일 전체 보기’를 켠 경우에만 이 PC의 화면에 원문을 표시합니다. 목록은 최신 5,000명까지이고 이 한도에 걸리면 안내합니다. 검색은 내려받은 명단의 전체 이메일 기준입니다.

개별 ‘상세 보기’에는 가입일·인증일·최근 인증 요청·대기 시간·인증 링크 만료 시각, 동의 항목·버전·시각, 최근 30일 메일 시도·API 수락 수와 최신 기록 최대 10개를 제공합니다. 원본 확인 토큰·서명·인증 링크·IP는 조회하지 않습니다. 원문 이메일을 포함한 명단도 기존 암호화 보고서 안에서만 전달하며 공개 정적 빌드·로그에는 넣지 않습니다. 전역 이력은 최근 5,000건까지 목록으로 읽으며 제한에 걸리면 안내하고 개별 합계는 별도 전체 집계를 사용합니다.

요약은 최근 7일 가입과 직전 7일 비교, 최근 7일 인증 완료, 현재 명단의 인증 완료 비율, 평균 가입→인증 소요 시간과 표본 수, 24시간 이상 대기·인증 링크 만료 수, 상위 8개 이메일 도메인 분포를 표시합니다. 가입·인증 차트는 7일/30일 선택과 일별 숫자 표를 제공합니다. 모두 현재 보관 중인 명단 기준이며 해지·만료 뒤 삭제된 사람은 과거 통계에서도 제외합니다. 따라서 누적 총가입자 수·해지율·완전한 과거 증가율로 표시하지 않습니다. 발송 조회일과 현재 명단 기준 시각도 구분합니다.

발송 탭에는 선택한 한국 날짜의 기록, 인증·정기·관리 메일 종류, API 수락·거절·한도 차단·결과 확인 필요 건수와 최근 7일 추이를 표시합니다. 본문 저장 기능 도입 이후의 메일은 확인·해지 토큰을 제거한 본문 미리보기를 제공합니다. 그 이전 메일의 본문은 Resend에서 확인해 주세요.

한도 패널은 Resend 무료 100통/일과 앱의 보수적인 90통/일 안전 예산을 구분합니다. 인증·관리 메일도 포함합니다. 한국 날짜별 내역과 UTC 날짜별 한도 기간을 별도로 표시하며, UTC 자정은 한국 시간 오전 9시입니다. 다음 정기 발송 예상은 현재 활성 구독자 수에 근거합니다. 예산이 80% 이상 사용됐거나 예상 수신자 수가 남은 예산을 넘으면 주의를 표시합니다.

이 수치는 이 서비스의 D1 발송 원장입니다. 다른 앱의 발송·수신까지 포함한 Resend 계정 전체 실측 사용량은 아닙니다. Resend Usage API는 full-access 키가 필요하므로 기존 도메인 제한 발송 키의 권한을 확대하지 않았습니다. 계정 전체·월 한도와 실제 배달·반송은 화면의 Resend 링크에서 확인합니다. API 수락을 실제 받은편지함 도착이라고 표시하지 않습니다.

연결은 기존 gh 로그인 → main의 monitor-newsletter.yml 수동 실행 → 짧게 유효한 OIDC 인증 → 서버에서 암호화 → GitHub 임시 암호문 → 이 PC에서 복호화입니다. 복호화 개인키와 복호화 결과는 메모리에만 보관하며, 평문 수신자·본문·구독자 수를 공개 GitHub 로그나 artifact로 내보내지 않습니다. 임시 암호문 artifact는 1일 후 만료합니다. 관리 서버는 무작위 로컬 포트의 127.0.0.1에만 바인딩하고 일회용 링크·HttpOnly/SameSite 쿠키·Origin/Host 검사로 보호합니다. 기존 게임 서버·터널과 연결하지 않습니다.

처음 열 때와 ‘지금 새로고침’에서 수집합니다. 기본은 수동이며 ‘5분마다 자동 조회’를 켜고 화면이 보이는 동안만 갱신합니다. 같은 날짜의 진행 중/대기 요청은 합치고 다른 날짜 요청은 앞선 조회가 실패해도 순서대로 처리하며, GitHub 실행 대기 때문에 즉시 끝나지 않을 수 있습니다. 실패하면 마지막 정상 데이터를 유지하고 수집 시각·오류를 표시합니다. 브라우저에서 더 이상 요청하지 않으면 로컬 서버는 30분 후 종료됩니다. PC를 꺼도 웹 발행·메일 발송은 계속되며 로컬 관리 화면만 종료됩니다.

조회 전용입니다. 재발송·구독자 삭제·한도 변경·과금 전환 버튼은 없습니다. 발송 단계는 D1 무료 쿼리 한도에 맞춰 한 요청당 6명, 한 실행당 16묶음 이하로 처리합니다. 하루 안전 예산 90통은 유지합니다. 운영 원문은 30일간 보관하며 확인·해지 토큰과 수신 주소 원문을 본문 사본에 추가 저장하지 않습니다.

필요 환경은 Node.js, 로그인된 GitHub CLI이며 이 PC에서는 기존 Codex Node 런타임과 gh 로그인을 사용합니다. 다른 PC에서는 같은 저장소의 workflow 실행·artifact 읽기 권한을 가진 계정으로 gh auth login을 완료해야 합니다. API 키를 채팅·공개 Git·HTML에 붙여 넣지 않습니다.
