# 원고를 소개하는 방식

이 원칙은 매일 작성하는 원고, 소개문, 그림, GPT 예약 프롬프트와 인계 문서에 동일하게 적용합니다.

- 독자에게 친숙하게 설명합니다. 기본 말투는 ‘~입니다’, ‘~해 보겠습니다’, ‘왜 그럴까요?’입니다. 딱딱한 ‘~한다’체나 과장된 홍보 문구는 피합니다.
- 기존 첫 원고의 난이도를 10으로 보면 목표는 8 정도입니다. 기술적 핵심과 실제 구현의 손익은 유지하되, 배경을 짧게 깔고 예제 하나를 끝까지 따라갑니다. 한 문단에서 새 용어를 너무 많이 소개하지 않습니다.
- 독자가 지금 풀려는 질문을 먼저 제시합니다. 이어서 작은 수치 예시나 그림으로 작동 방식을 확인하고 코드·엔진으로 연결합니다. 지엽적인 내부 함수·역사·예외는 꼭 필요할 때만 넣거나 더 읽을거리로 보냅니다.
- 핵심 용어는 처음 필요한 지점에서 한국어(English)로 설명합니다. API·클래스 이름은 원문 그대로 쓰며 의사 코드와 실제 API를 구분합니다.
- 직접 만드는 그림은 **다크 모드**가 기준입니다. 배경 #080f17, 패널 #13202c, 본문 #f3f0e8, 보조 글자 #a2afab, 강조 #d9eea6을 바탕으로 대비를 확보합니다. 원문 이미지의 색을 임의로 고치지는 않습니다. 도식의 수치·시간 순서·범례는 코드와 벡터로 검증합니다.
- 마지막 실질적인 본문 절은 **오늘 얻어갈 것**입니다. 도입 질문의 답과 실제로 확인할 코드·엔진·프로파일러 지점을 설명합니다.
- 모든 공개 원고는 정식 글로 취급합니다. 샘플·데모·가짜 호를 공개 목록에 채우지 않습니다. 예약 준비 중에는 scheduled, 실제 공개 시에는 published를 사용합니다.
- 읽기 시간 표시는 넣지 않습니다. 주요 사실의 1차 출처, 날짜·버전, 이미지의 출처·캡션·대체 텍스트는 유지합니다.
