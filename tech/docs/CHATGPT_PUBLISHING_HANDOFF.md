# ChatGPT 인계 — 겜붕이의 노트

운영 시작 기준일은 2026년 11월 3일이며, 실행·검사 안내는 11월 5일 갱신했습니다. 시간대는 Asia/Seoul입니다. 이 문서는 이전의 미배포·샘플·Direct Upload·파일 기반 메일 CLI 인계를 대체합니다. 비밀값과 개인 수신 주소는 포함하지 않습니다.

## 운영 주소와 구조

- 운영 사이트는 https://tech.teamhjd.com/ 이며 기본 주소는 https://gambungi-notes.pages.dev/ 입니다.

- Cloudflare Pages 프로젝트는 gambungi-notes입니다. Git integration, root=tech, build=npm run build:cloudflare, output=dist를 사용합니다. 회사 홈페이지의 기존 GitHub Pages 배포는 별도입니다.
- 글 목록 /, 태그 검색 /tags/, 구독하기 /subscribe/를 별도 페이지로 제공합니다. 동의·인증·해지 안내는 /subscription/ 아래에 있습니다.
- 2026년 11월 3일 첫 정식 글은 ‘먼저 움직이고, 과거를 고칩니다’입니다. 예전 경로 호환을 위해 ID frame-2026-11-02와 slug client-side-prediction은 유지했습니다. 새 호에서 이 예외를 따라 날짜를 어긋나게 만들지 않습니다.

- 글 주소는 /YYYY-MM-DD/제목-slug/입니다. 첫 글은 https://tech.teamhjd.com/2026-11-03/client-side-prediction/ 입니다. 예전 /articles/client-side-prediction/은 새 주소로 301 이동합니다. RSS·목록·검색·메일도 날짜가 들어간 주소를 사용합니다.

## 말투·난이도·디자인 원칙

EDITORIAL.md를 함께 읽어 주세요. 원고·소개·인계 문서는 친숙한 존댓말을 사용합니다. ‘~입니다’, ‘~해 보겠습니다’, ‘왜 그럴까요?’가 기본입니다. 초기 원고의 난이도 10을 기준으로 목표는 약 8입니다. 작은 예제 하나를 끝까지 설명하고, 기술 핵심과 실제 구현의 손익은 유지해 주세요.

첫 화면 문구는 ‘매일 하나씩 알아가는 호기심 가득한 게임 개발.’입니다. 작은 부제목은 ‘하루 10분의 호기심이 쌓여, 게임 개발을 바라보는 깊이가 달라집니다.’입니다. 그 아래에 ‘매일 낮 12시, 새로운 노트를 이메일로 보내드립니다.’를 표시하며 구독 페이지에도 한국 시간 낮 12시 발송을 안내합니다. GAME DEVELOPMENT NOTES 같은 위쪽 영문 문구는 사용하지 않습니다. 브랜드는 겜붕이의 노트, 작은 표기는 by TeamHJD입니다. 손그림 로켓은 원본 픽셀을 재사용합니다. 헤더 워드마크와 탭 아이콘은 용도가 다릅니다. 탭 아이콘은 회사 공통 v1의 notes 배지 파일을 그대로 사용합니다.

색·폰트·푸터는 teamhjd.com을 기준으로 맞췄습니다. scripts/company-brand.mjs가 회사 루트 styles.css와 index.html 푸터·워드마크를 가져옵니다. 회사 사이트의 관련 사이트에도 겜붕이의 노트를 연결했습니다. 매일 원고 작업에서 이 코드를 수정하지 않습니다.

직접 만드는 그림은 다크 모드를 기준으로 합니다. 배경 #080f17, 패널 #13202c, 본문 #f3f0e8, 보조 글자 #a2afab, 강조 #d9eea6입니다. 수치·화살표·범례는 검증 가능한 코드·벡터로 제작해 주세요. 원문 이미지와 직접 만든 개념도를 구분합니다. 원문 이미지는 색을 임의로 바꾸지 않습니다. 확대 팝업에는 그림 전체가 들어오도록 맞추고, 원본 해상도는 별도 링크로 엽니다.

모든 공개 글은 정식 발행입니다. 샘플·데모·가짜 호로 목록을 채우지 않습니다. 읽기 시간은 넣지 않습니다. 마지막 실질적 절은 ‘오늘 얻어갈 것’이며, 그 뒤에 출처를 둘 수 있습니다. 주요 사실과 최신 버전은 1차 자료로 검증해 주세요.

## 매일 발행하는 역할과 시간

ChatGPT의 **기존 클라우드 예약을 매일 11:00 Asia/Seoul**에 실행해 조사·원고·그림·GitHub 반영을 맡깁니다. **11:57 웹 공개·이메일 발송 시작과 12:03 재점검은 GitHub Actions·Cloudflare Pages Functions·Resend**가 맡습니다. 목표는 정오까지 하루 한 호를 한 번 수신하는 것입니다. GitHub·배포·메일 큐의 지연으로 정오까지 도착을 절대 보장하지는 않습니다. 사용자 컴퓨터를 켜 둘 필요가 없습니다. 별도 유료 AI API 생성 서버는 사용하지 않습니다.

ChatGPT는 CONTENT_CONTRACT.md에 맞춰 당일 호를 status=scheduled, publishAt=YYYY-MM-DDT11:57:00+09:00으로 반영합니다. 이 상태는 웹·다운로드·RSS에서 제외합니다. 공개 Git의 scheduled는 비공개 초안 저장이 아니므로 민감한 내용을 넣지 않습니다.

Publish newsletter at noon KST가 11:57에 첫 공개·발송 절차를 시작하고 12:03에 재점검합니다. 검증된 당일 호 하나만 published로 바꾸고 실제 공개 시각 publishedAt을 기록한 뒤 main에 커밋합니다. Cloudflare가 빌드·배포합니다. 같은 날 이미 발행한 호가 있으면 다시 공개하지 않습니다. 원고가 없거나 검사가 실패하면 지난 호로 대체하지 않습니다. 새 공개의 마감은 12:30이며, 그 이후 준비되지 않은 글은 자동 지연 공개하지 않습니다.

메일 단계는 운영 publication.json에 해당 ID가 나타날 때까지 기다린 후 실제 발송을 요청합니다. 12:03에는 같은 당일 호에서 아직 발송을 시도하지 않은 대상만 점검합니다. 같은 호·구독자 조합에 receipt가 있으면 재발송하지 않으며, 응답 유실 등 불명확한 기록도 지우거나 자동 재전송하지 않습니다. 재점검은 두 번째 뉴스레터를 보내는 절차가 아닙니다.

## 이 문서를 받은 GPT가 해야 할 예약 설정

초기 Codex 인계는 ChatGPT의 기존 예약을 조회·수정하지 않았습니다. 전달받은 예약 ID는 6ae774bba4148191961bb42f0e193d6b이며 당시에는 일시 중지·12시 설정이었습니다. 이후 기존 예약을 매일 11:00 Asia/Seoul로 갱신했습니다. 다음 운영 작업에서도 실제 현재 상태를 먼저 확인해 주세요. 예전 ID 6ae770fa2b148191b9db1650b0dc6a08도 함께 켜 중복 실행하지 않습니다.

1. 최신 DAILY_RELIABILITY.md, RECOVERY.md, OPERATIONAL_AUDIT_20261105.md, 이 문서, EDITORIAL.md, CONTENT_CONTRACT.md, CHATGPT_DAILY_PROMPT.md를 읽어 주세요.
2. 연결된 GitHub에서 main을 읽고 실제 콘텐츠 쓰기 도구가 있는지 확인해 주세요. 로컬 폴더에 의존하지 않습니다.
3. 일반 채팅에서 원고 준비와 GitHub 반영을 한 번 시험해 주세요. 오늘 이미 정식 발행된 호가 있으면 오늘의 두 번째 호를 만들지 않습니다. 내일 원고를 미리 준비하는 경우 date와 publishAt을 내일로 맞추고 scheduled를 유지합니다.
4. 기존 예약의 편집 의도를 보존하며 CHATGPT_DAILY_PROMPT.md를 적용하고 매일 11:00 Asia/Seoul 설정을 유지해 주세요. 실제 클라우드 도구와 권한이 확인된 뒤 활성화합니다.
5. Run now로 한 번 시험하고 실제 원고·이미지·커밋·CI 결과를 확인해 주세요. 예약이 생성됐다는 사실만으로 무인 반영 성공이라고 말하지 않습니다.
6. 11:57 공개·발송과 12:03 재점검 실행에서 Actions, Cloudflare 배포, publication.json, 기사·그림·다운로드를 확인해 주세요. 원고 준비·웹 공개·API 발송 수락·실제 이메일 수신은 구분해 보고합니다.

예약 실행에서 쓰기가 승인 대기로 멈추거나 도구가 읽기 전용이면, 그 제한을 사용자에게 알려 주세요. 공개 권한을 확대하거나 다른 서비스로 몰래 대체하지 않습니다.

## GitHub 콘텐츠 반영 범위

원고 준비 후 사전 기동은 DAILY_RELIABILITY.md 및 RECOVERY.md가 우선합니다. tech/operations/release-request.json 하나만 별도 커밋으로 추가 허용하며 실제 run ID를 확인합니다. 이미 scheduled여도 기동 확인을 생략하지 않습니다. GitHub cron은 보조입니다.

허용된 콘텐츠 변경은 tech/content/issues.json, tech/content/tags.json, 이번 호의 tech/content/issues/<id>.md와 tech/assets/issues/<id>/입니다. 기존 배열·호·타인의 변경을 보존하고 최신 HEAD를 기준으로 일관된 커밋 하나를 만들어 주세요. 가능하면 GitHub의 blob → tree(base 지정) → commit(parent 지정) → update_ref(expected SHA, force=false) 흐름을 사용합니다. 실제 도구가 제공되는지는 실행 때 확인합니다.

브랜치 보호 때문에 main 쓰기가 안 되면 콘텐츠 PR을 만들고 pending으로 보고해 주세요. 자동 병합이나 무인 배포가 끝났다고 주장하지 않습니다. 코드·브랜드·워크플로·DNS·권한·Secrets·구독 DB·발송 기록은 GPT의 매일 작업 범위가 아닙니다. 개인 주소나 키를 공개 Git에 넣지 않습니다.

## 구독과 메일 운영

구독 신청에는 개인정보 수집·이용, 뉴스레터 이메일 수신, 국외 이전 동의를 각각 받습니다. 미리 선택하지 않습니다. 메일 링크를 열기만 해서는 활성화하지 않으며, 확인 버튼을 누른 뒤 active가 됩니다. 확인 링크는 24시간 유효하고, 미확인 신청은 7일 후 정리합니다. 해지는 서명된 링크에서 버튼을 눌러 처리하고 이메일 주소를 삭제합니다. 원클릭 해지 헤더도 제공합니다.

인증 메일 발송을 수락한 뒤에는 이메일·동의 입력과 구독 버튼을 잠그고 ‘인증 대기 중’을 표시합니다. 대기 중 창 닫기·이동에는 beforeunload 경고를 연결합니다. 브라우저 기본 문구를 사용하며 표시 여부는 브라우저의 사용자 동작·지원 조건을 따릅니다. 신청 탭은 24시간짜리 임의 상태 토큰으로 서버를 확인합니다. 다른 탭에서 인증이 끝나면 BroadcastChannel과 서버 조회로 원래 신청 탭을 ‘구독 완료’로 갱신하고 경고를 해제합니다. 이메일 앱이 여는 탭 자체를 강제로 바꾸거나 새 창을 추가로 열지는 않습니다.

구독 관리·해지는 https://tech.teamhjd.com/subscription/manage/ 에서 가능합니다. 구독 페이지와 모든 페이지의 푸터에 링크를 제공합니다. 이메일을 입력하면 해당 주소로 관리·해지 메일을 보내며, 서명된 해지 페이지에서 버튼을 누르면 주소가 삭제됩니다. 인증 메일에도 ‘신청 취소·구독 해지’, 정기 메일에는 ‘구독 해지하기’를 본문에 분명히 표시합니다. 관리 메일을 요청하는 것만으로 다른 사람의 구독을 해지하지 않습니다.

메일은 원본 손그림 로켓과 겜붕이의 노트 워드마크 PNG, 작은 by TeamHJD, 회사 다크 색상, 핵심 버튼·별도 해지 버튼·개인정보·문의 링크를 갖춘 HTML과 일반 텍스트를 함께 보냅니다. 메일용 PNG는 기존 워드마크 SVG를 렌더링한 것이며 로켓을 새로 그리지 않습니다. 클라이언트별 실제 받은편지함 표시 범위는 실행 기록을 확인해 주세요.

사이트 CSS·JS와 직접 만든 글 그림은 내용 해시가 붙은 URL을 사용합니다. 그림을 수정하면 본문·확대 원본·다운로드 Markdown까지 새 버전을 가리킵니다. 11월 3일 PNG 3개는 운영 바이트와 동일함을 확인했고 SVG는 줄바꿈 차이를 정규화해 내용 동일함을 확인했습니다. 이후 SVG도 LF로 고정했습니다. 기존 공개 ID·날짜를 바꿔 캐시를 피하지 않습니다.

카카오톡 등 링크 미리보기에는 원본 손그림 로켓과 겜붕이의 노트 워드마크, 작은 by TeamHJD, ‘매일 12시에 읽는 노트들’을 담은 공통 1200×630 PNG를 사용합니다. 기사 제목·설명은 각 글에 맞게 유지하며 공유 이미지 주소는 /assets/brand/gambungi-share-v1.png입니다. 공유 이미지도 다크 색상이며 화면 테마와 별개입니다. 사이트 푸터는 화면의 다크·라이트 모드를 따라 배경·글자·워드마크 대비·관련 사이트 메뉴를 함께 바꿉니다.

비공개 D1 데이터베이스 gambungi-notes-subscribers를 Pages의 DB 바인딩으로 사용합니다. 미국 관할로 생성했습니다. 발송자는 겜붕이의 노트 <notes@news.teamhjd.com>이며 Resend의 도쿄 리전 도메인을 사용합니다. 발송 전용·도메인 제한 API 키는 Pages의 RESEND_API_KEY 암호화 비밀값에만 저장합니다. 확인·해지 서명과 비식별 해시에는 별도 TOKEN_SECRET을 사용합니다. 키는 GitHub·문서·채팅으로 전달하지 않습니다.

Resend 무료 플랜을 사용하며 이 앱은 인증·관리 메일을 포함해 하루 최대 90건으로 제한합니다. 제공자의 무료 100건/일 한도에 여유를 둔 값입니다. 다른 앱이 같은 계정의 한도를 쓰거나 월 한도에 도달하면 실패할 수 있습니다. 유료 전환은 자동으로 하지 않습니다. D1 무료 쿼리 한도를 지키기 위해 한 요청당 최대 6명, 한 실행당 16묶음 이하로 처리합니다.

운영자는 tools/Open-NewsletterMonitor.ps1로 로컬 HTML 관리 화면을 엽니다. 요약·통계 / 구독자 목록 / 발송 내역 탭에서 활성·대기 명단의 검색·정렬·개별 상세, 가입·인증 추이와 동의 기록, 일별 발송 내역, 안전 예산, 토큰을 제거한 새 발송 본문을 확인합니다. 명단은 기본 마스킹이며 전체 이메일은 운영자가 로컬에서 명시적으로 표시합니다. 가입 통계는 현재 보관 명단 기준으로 삭제된 사람을 포함한 누적 가입·해지 통계가 아닙니다. 보고서는 서버에서 암호화되며 GitHub에는 임시 암호문만 저장하고 복호화 키는 해당 PC 메모리에만 둡니다. GPT의 매일 원고 작성 작업에서는 이 관리 도구를 호출하거나 수신자·발송 기록을 수정하지 않습니다. 자세한 동작과 한도 집계의 범위는 LOCAL_MONITOR.md를 확인해 주세요.

정기 발송 API는 짧게 유효한 GitHub Actions OIDC를 검증하며 정확한 저장소의 변경되지 않는 ID·소유자 ID·main·발행 워크플로만 허용합니다. 실제 계정의 ID가 들어간 sub 형식을 기준으로 검증합니다. 장기 발송 관리자 키를 GitHub에 보관하지 않습니다. 임의 수신자·임의 본문은 받지 않고 실제 공개된 당일 호를 읽습니다. D1 영구 발송 기록과 Resend Idempotency-Key로 중복을 막습니다. 응답 유실 등 불명확한 발송은 자동 재전송하지 않습니다. 운영자가 제공자 기록을 확인하기 전에는 receipt를 지우거나 호 ID를 바꾸지 않습니다.

클릭·열람 추적은 끕니다. API의 queued는 제공자가 발송을 수락했다는 뜻이며 받은편지함 도착을 보장하지 않습니다. 구독 목록·집계·관리 UI는 공개하지 않습니다. 기존 integrations/cloudflare-email.mjs는 이전 영구 디스크용 도구이며 현재 공개 구독 서비스의 발송 경로가 아닙니다.

## 검사와 실제 확인 상태

표 앞 빈 줄이 없으면 운영 변환기에서 문단으로 출력되는 문제를 2026년 11월 6일 수정했습니다. 같은 형식은 이제 원고 검사에서 차단합니다. 표 앞뒤에 빈 줄을 두고 코드 fence에는 실제 언어(cpp·csharp·glsl·hlsl 등)를 표시해 주세요. 코드 문법 색상은 사이트가 Visual Studio 계열의 다크·라이트 색상으로 자동 적용합니다.

글 하단에는 공통 템플릿으로 네 가지 반응 버튼을 제공합니다. [글 반응 수집](ARTICLE_FEEDBACK.md)을 참고해 주세요. 새 원고 본문에 버튼이나 추적 코드를 붙이지 않습니다. 운영자가 제공한 글별 집계가 있을 때에만 다음 주제·난이도 조정에 참고하며, 매일 원고 작업에서 비공개 관리 조회나 개별 식별값 조회를 자동 실행하지 않습니다.

[작업별 실행·완료 처리](WORKFLOW_COMPLETION.md)를 함께 읽어 주세요. 콘텐츠 검사, 회사 사이트 배포, 비공개 관리 조회, 당일 발행은 목적이 다른 실행입니다. 실패 알림만 보고 동일한 발행 요청을 다시 만들거나 실행을 취소하지 않습니다. 실제 단계 로그와 최종 진단을 확인하고, 불명확한 발송 결과는 기존 receipt를 유지한 채 확인합니다. 실패해도 독립 검사·진단 artifact·최종 요약까지 수행하며, 필수 검사가 실패한 글을 강제로 공개하거나 발송하지 않습니다. C++의 완전한 inline code 안에 있는 `<new>` 등은 정상적인 코드로 검사합니다.

소스 검사는 Node 22 이상과 Pandoc으로 수행합니다. npm run validate, npm run test:content, node --test src/subscriptions.test.mjs, npm run build를 사용합니다. Cloudflare 빌드와 Validate newsletter는 기존 검사와 구독 검사를 함께 실행합니다. Pandoc이 없으면 공식 3.13 Linux 파일을 고정 SHA256으로 확인해 임시 사용합니다.

최종 실행·배포·실제 메일 확인 결과는 함께 전달하는 실행 기록을 확인해 주세요. 2026년 11월 3일 기존 정오 발송 경로의 실행이 성공했으며 사용자가 실제 뉴스레터 수신을 확인했습니다. 로컬 관리 조회에서도 정기 메일의 API 수락을 확인했습니다. 테스트 성공·API 수락·실제 받은편지함 도착은 구분해야 합니다. 이 과거 확인을 새 11:57·12:03 일정의 무인 실행 성공으로 간주하지 않으며, ChatGPT 원고 준비 예약과 새 발송 일정의 실제 실행은 각각 기록으로 확인합니다.

원고 외 운영 코드를 손봐야 할 때에는 기존 Codex 작업에서 점검해 주세요. 매일 원고를 작성하는 GPT가 새 키 발급·구독자 조회·해지 처리·수신자 재발송을 수행하지 않습니다. 사용자가 직접 구독 관리 페이지에서 요청하는 흐름을 유지합니다.
