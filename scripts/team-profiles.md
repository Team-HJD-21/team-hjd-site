# 팀 프로필 관리

양현석·황재동·김진태·이영빈·조수빈 다섯 명의 정적 프로필입니다. 참여자 목록 순서는 유지하며 사용자 제공 정보만 표시합니다. 역할은 추측해서 추가하지 않습니다. `main` push 시 기존 GitHub Pages 워크플로가 정적 검사·프로필/모션 검사·빌드를 수행하고 배포합니다. 아래 검증 기록의 배포 여부는 각 작업 당시의 상태입니다.

## 구조와 정보 수정

- `data/team.mjs`의 `members`: 공개용 개인 정보의 단일 원본. `name`, `englishName`, `shortBio`, `links` (`label`, `href`, `icon`), `contactEmail`, `image` (`src`, `alt`, `position`), `interests`를 수정합니다. 사진 파일은 `assets/team/`에 둡니다.
- `organizationTitle`: 회사 직책의 언어별 공개 표기입니다. 공동대표는 스튜디오 영역의 명단으로 표시하며 프로젝트 팀에는 직책을 표시하지 않습니다.
- `projects[].participants`: 기존 참여자 순서를 유지합니다. `memberId`로 사람을 연결하고, 운영자가 확인한 해당 프로젝트의 `roles`만 입력합니다. 2026-10-16 사용자 제공 역할을 간추려 표시합니다. 양현석: Lead / Core Systems / UI, 황재동: Defense / Progression / Balance, 김진태: World / Missions / Ally Agent, 이영빈: Player / Combat/Co-op / Cinematics, 조수빈: Enemy / Encounter / AI. 관심 분야로 역할을 추측하지 않습니다.
- 새 사람은 고유 `id`와 안정적인 `slug`를 지정해 `members`에 추가합니다. 공개할 프로필이 준비되면 `profileEnabled: true`를 설정하고 해당 프로젝트의 `participants`에 연결합니다. 이름이 바뀌어도 `id`와 `slug`는 유지합니다.
- 같은 사람을 다른 프로젝트에 연결할 때는 기존 `memberId`와 그 프로젝트의 역할만 추가합니다. 개인 정보를 복사하지 않습니다. `renderRoster(project)`와 하나의 프로필 URL을 재사용합니다. 새 프로젝트 자체의 홈페이지 영역은 별도로 추가해야 합니다.
- 선택 항목을 공개하지 않을 때는 원본 데이터에서 필드를 삭제하거나 빈 값으로 둡니다. `X`도 숨겨지지만 삭제를 권장합니다. 링크·관심 분야는 빈 배열로 둘 수 있습니다. 비공개 정보는 이 공개 데이터 파일에 저장하지 않습니다.
- 이번 사용자 요청에 따라 외부 링크 세 개 모두 표시합니다. 새 링크는 HTTPS 주소와 목적을 알 수 있는 이름을 입력합니다.

## 생성과 실행

```powershell
node scripts/render-team.mjs
node scripts/check-site.mjs
node scripts/test-team.mjs
node scripts/build-site.mjs
node scripts/preview-site.mjs _site 4173
```

기본 빌드 출력 `_site`가 이미 있으면 기존 결과를 삭제하지 말고 빈 별도 디렉터리를 인자로 전달합니다. 미리보기는 `http://127.0.0.1:4173/team/yang-hyunseok/`입니다. Windows 샌드박스에서 브라우저 연결이 거부되는 경우 정상 승인된 로컬 서버 실행이 필요할 수 있습니다. 방화벽이나 전역 보안 설정을 변경하지 않습니다.

`scripts/team-template.mjs`가 공통 프로필 카드와 페이지를 렌더링합니다. 헤더·푸터는 홈페이지 마크업을 재사용합니다. `team/*/index.html`과 메인의 `team-roster` 마커 내부는 생성 결과이므로 직접 수정하지 않습니다. 빌드 시에도 자동 재생성합니다. 프로필을 끌 때 이미 생성된 페이지를 자동 삭제하지 않으므로, 공개를 철회할 때는 해당 `team/{slug}/` 생성 페이지와 사용하지 않는 이미지도 저장소에서 별도로 제거해야 합니다.

`profile.css`는 카드/명단/모바일 스타일, `profile.js`는 커서 기울기와 빛 반사입니다. 커서 기울기는 터치 및 동작 줄이기에서는 실행하지 않습니다. 이미지가 없어도 텍스트 전용 카드가 렌더링됩니다. 실제 링크와 한국어 본문은 JavaScript 없이도 동작합니다.

사진 카드에는 기존 회사 로고에서 로켓 부분만 CSS로 잘라 보여줍니다. 로고 PNG 원본은 수정하지 않습니다. 별·사진 하단 슬로건·커서 안내 문구는 표시하지 않습니다. 첫 진입 시 로켓이 있는 뒷면에서 사진 앞면으로 1.8초 동안 180도 회전하며 작은 감속 동작으로 안착합니다. 회전이 끝날 때 연두색 빛이 잠깐 밝아지고 반사광이 한 번 지나간 뒤 은은한 빛만 남습니다. 이 진입 효과는 터치에서도 재생되지만 동작 줄이기 설정에서는 건너뛰고 바로 앞면을 보여줍니다. 커서 기울기는 별도 외부 요소에서 처리하고 진입 회전이 끝난 뒤 시작합니다. 실제 시간에 따른 감쇠로 커서를 부드럽게 추적하며, 사진의 작은 시차 이동과 테두리 반사를 함께 적용합니다. 커서가 나가면 천천히 원위치로 돌아오고 프레임 루프를 멈춥니다. 프로필 본문 아래 여백은 PC 108px, 모바일 76px입니다.

스튜디오 공동대표 명단은 `renderStudioLeadership()`과 `studio-leadership` 마커로 생성합니다. 이 명단에서 프로필을 열면 돌아가기 링크는 `#studio-leadership`을 가리킵니다. 프로젝트 명단에서는 `#project-team`으로 돌아옵니다. 프로젝트 역할은 제공된 영어 약식 표기를 모든 언어에서 유지합니다.

폴리싱 참고: [Motion 3D transforms](https://motion.dev/docs/3d-transforms), [web.dev animation performance](https://web.dev/articles/animations-guide), [W3C C39 reduced motion](https://www.w3.org/WAI/WCAG22/Techniques/css/C39). 3D 앞·뒷면 구성과 커서 좌표 매핑, transform/opacity 위주의 전환, 동작 줄이기를 참고했습니다. 라이브러리·외부 스크립트는 추가하지 않았습니다.

### 모바일 카드 뒷면 비침 수정 (2026-10-16)

- 사용자 보고 환경: 아이폰 Chrome. 간헐적으로 진입 회전의 뒷면에도 사진이 표시됨. 실제 아이폰에서 직접 재현한 것은 아니며, 내부 요소가 독립적인 3D 층을 갖는 기존 구성을 원인 후보로 확인했습니다.
- 회전 컨테이너만 `preserve-3d`로 유지하고 각 면은 `flat` + 클리핑/격리로 합성합니다. 사진·이름·빛 효과가 각 면의 한 표면으로 숨겨지도록 하고, 자식의 backface 숨김도 상속합니다. 앞뒷면은 1px씩 분리해 같은 평면의 겹침을 피합니다. 이름의 Z 이동을 제거하고 사진 시차는 2D 이동으로 유지합니다.
- 참고: [WebKit 3D transforms](https://webkit.org/blog/386/3d-transforms/), [Apple Safari visual effects guide](https://developer.apple.com/library/archive/documentation/InternetWeb/Conceptual/SafariVisualEffectsProgGuide/Using2Dand3DTransforms/Using2Dand3DTransforms.html).
- 로컬 회귀 화면 생성: 빌드 후 `node scripts/render-profile-face-check.mjs <빌드 출력 폴더>`. 해당 폴더의 `/qa/mobile-backfaces/`에서 다섯 프로필 각각의 0°·60°·120°·180°를 확인합니다. 0°·60°는 사진/null, 120°·180°는 로켓만 보여야 합니다. 이 QA HTML과 생성 스크립트는 공개 빌드에 복사하지 않습니다.
- 실제 확인: Windows Chrome 및 Codex in-app Chromium의 20개 각도 사례에서 뒷면에 로켓만 표시. Chrome 320/375/390/412/430/768px에서 가로 넘침 없음. 사진/문구의 backface 숨김과 각 면의 평면 합성, 실제 진입 애니메이션도 확인했습니다. 정적 검사·프로필/모션 검사·빌드 통과.
- 검증 한계: 연결 가능한 실행 환경에 Safari/WebKit/Firefox 및 아이폰·갤럭시 실물 기기가 없습니다. 따라서 Safari, iOS Chrome, Android Chrome, Samsung Internet의 실기기 통과를 주장하지 않습니다. 화면 폭 변경 검사는 해당 기기의 엔진/터치 환경 검증을 대신하지 않습니다.
